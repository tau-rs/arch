The shell: one bar, the rail and left panel, a bottom panel, a status bar

The frame is fixed: the Map in the center, always, with the plan on it; the inspector on the right, about the selection. Only the left panel changes, and a 56 px rail picks what it shows: Sessions on top (every session, its agents, their sub-agents, what each edits), Files (the structure of a worktree, projected by directory or by layer) and Findings (the repo's findings by rule). The rail carries the badges, survives the pane being closed, and shows the scope as a thin colour bar on the active label. A scope line at the top of the pane says which worktree it shows, in the same words and colour as the crumb and the frame, so swapping views never leaves you guessing.

Scope: one word, three places

The scope is which worktree the shell is about: main, or a session's worktree. It is set by focusing a session: the Focus button on its selected row, the card's first button, Enter, a chip that names it, or the scope selector in the top bar; and it is cleared with Esc, ‹ All sessions, or by choosing main in the selector. It is written in exactly three places, always with the same words and colour: the scope line of the left panel, the crumb in the Actions strip, and the frame border. The Files view never changes scope by itself: switching Files ↔ Sessions keeps the scope, and Files shows the focused worktree and nothing else. To see another worktree's files, focus another session, or Esc to main; there is no second control for it. Selecting a session in the Sessions view (single click) lights it on the Map and shows its card, but does not change the scope; that is what keeps a glance from becoming a jump.

When you are looking at code

A file tab is open in the center, the Map reduced in the right pane. The left panel stays, and its view is whatever you were in: Files reveals the open file in the tree (Directory) or the item it belongs to (Layers), which is the “where am I” the Layers projection exists for; Sessions keeps the agent writing that file highlighted, so you see who is in the file with you. ⌘B hides the pane for a wide read and brings it back in the same state; the rail stays, with its badges and the scope bar on the active label. The scope line does not move; the tab's header repeats the scope (“w1 · a2 editing”) because a tab can outlive a scope change.

Plan

The plan is never off the Map: the plan overlay paints elements and waves, and the plan chip opens plan focus, which keeps the Map in the center with the planner in the right pane. The left panel stays available in plan focus, on Files · Layers by default, since planning is done in architecture terms; ⌘B hides it.

One line on top

The top bar and the Actions strip were saying the same thing twice: the crumb was the scope and the branch selector was the scope. They are one 44 px line now: arch · orderly › [scope selector] on the left, where the selector reads main, w1 · refund flow in its colour, or you · fix-pool-size 🔒; in plan focus it gains › plan › refund flow. Then the chips, right-aligned, only the ones that carry a verb: a question to answer, a plan to open, a gate to step into, changes to commit, a plugin to install. Then Ask ⌘K. Presence pills are dropped: a session that needs you is a chip, a count on the rail's Sessions badge, and a word in the status bar; three places is enough.

Invariants

LEFT-1
The rail holds views of the repo, three labels. Sessions first, then Files, then Findings; glyph and horizontal label, never icons alone, never vertical text. Plugins, settings and search live elsewhere. A fourth label needs a fourth collection.
LEFT-0
The rail never hides. The pane does (⌘B or the active label); the rail keeps its badges and the scope bar, so nothing that needs you leaves the screen.
LEFT-2
The scope is written in three places with the same words. Scope line, crumb, frame. Switching views never changes it; only a double-click, a chip, Esc, or the scope line's ▾ does.
LEFT-3
Files has two projections of one worktree, and one selection with the Map. Selecting in the pane lights the item and its relations on the Map; selecting on the Map reveals it in the pane. Reading the project never closes the pane: it is the navigation.
LEFT-3b
Looking is not jumping. A single click selects and shows, a chevron folds; the scope changes only through a visible Focus, which also isolates the session in the pane. Esc goes back to all sessions.
LEFT-4
Sessions shows containment. Session › lane › sub-agent › files edited. Files edited appear under the agent that edited them, with the letter and counts; they are the same files the Files view bars.
LEFT-5
The Map and the plan are never displaced. Code opens as tabs with the Map reduced in the right pane; plan focus keeps the Map; the left panel is the only thing that changes.
LEFT-7
A session need not have an agent. A manual session is your own worktree with the same card, files and git; locking it pins the scope so looking around never moves your edits.
LEFT-8
In Files, the agent tree lives under the scope. It is the same tree as in Sessions, collapsed to the selected agent's path; selecting an agent there changes the ink in the tree, never the scope.
SHELL-1
One line on top. Brand, repo › scope selector, verb-chips, Ask. The scope selector is the crumb; nothing is written twice.
SHELL-2
The panel lists what arch already produces. Findings, Checks, Terminal, What's new; a tab is a list behind a chip or a flow, never a new feature.
SHELL-3
The status bar is counts and states. No verbs; each item opens the view or tab that owns it.
LEFT-6
Colour is the only presence mark on a file. One colour per session; the writer's label appears only when scoped.
